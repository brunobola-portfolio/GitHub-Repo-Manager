## Modal-header canonicalization

Audit grep:

```bash
grep -rln 'isOpen.*onClose' src/components --include='*.jsx' \
  | xargs -n1 grep -l '<h1\|<h2[^>]*text-xl\|<h2[^>]*text-2xl' 2>/dev/null \
  | grep -v 'PageHeader.jsx'
```

**Outcome:** No actionable findings. Existing modals either pass `title` / `description` to the `Modal` primitive (which renders a canonical header internally) or use a contextual `<h2>` for in-body sections (which is correct — those aren't modal-level titles). The new `QuotaExceededState` and `OnboardingTour` use their own bespoke layouts intentionally because they're full-screen overlays rather than chrome-wrapped modals; both ship with `role="dialog"` + `aria-modal="true"` + `aria-label` for screen readers.

If a future modal lands a hand-rolled header that doesn't go through PageHeader or Modal's slot, it should be migrated as part of that PR — not retroactively in this audit.
