## Top observations

1. **`esm-*.js` is a catch-all** for node_modules that aren't matched by the existing `manualChunks` rules in `vite.config.js`. The rules currently split out: react, recharts, framer-motion, lucide-react, @radix-ui, react-markdown. Everything else (sentry, simple-git client wrappers, octokit, swr, jose, zod, date-fns, etc.) lands here. The rolldown `IMPORT_IS_UNDEFINED` warnings about `@sentry/react.getCurrentHub` confirm Sentry is in this chunk.

2. **CSS is 43 KB gzipped** (mostly Tailwind utilities). For a 290+ component app, this is reasonable but worth tracking — slice 4.3 (`ds-*` orphan removal) trims a bit.

3. **Code-splitting works for routes.** MigrationWizard, SettingsModal, RepoDetail, WorkBoardPage, DevToolkitPanel, DashboardPremium, PRReviewView are all lazy chunks (24-100 KB gzipped each). Initial render only loads `index` + `vendor-react` + critical CSS ≈ **160 KB gzipped**, which is decent first-paint.

## Findings

- 📋 **High:** `esm-*.js` at 332 KB gzipped is the single biggest cost on first page load if it's eagerly imported. Investigate which deps land in it (treemap drills down) — sentry, octokit, simple-git client are the prime suspects. If `@sentry/browser` is the bulk, audit whether we actually need its replay/profiling submodules or just the core `init`.
- 📋 **Medium:** vendor-charts (recharts at 108 KB gzipped) loads eagerly via the Dashboard route. Confirm the dashboard *needs* recharts on first render; if Sparkline-only usage, a lighter alternative (e.g. `react-sparkline` ~5 KB) would save ~100 KB gzipped on cold visits.
- 📋 **Low:** vendor-motion (41 KB gzipped) is fine — framer-motion's `motion()` API is used widely; tree-shaking already excludes the gestures module.

## Real-world impact

- **Cold cache, slow 4G (1.5 Mbps):** ~4.0s to download the eager bundle (160 KB gz initial + 332 KB esm if eager). Two of those seconds are the `esm` chunk alone.
- **Cold cache, fast WiFi (10 Mbps):** ~600ms total. Acceptable but the esm chunk is the bottleneck.
- **Warm cache:** instant; chunks hash-stable except when their content changes.
